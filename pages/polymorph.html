Polymorph AI

CLI que eu construí e uso nas minhas próprias candidaturas — incluindo essa

Google Gemini API Python (Typer) Playwright Jinja2

O Problema

Quando comecei a me candidatar para estágios, percebi que o mesmo currículo não funcionava para vagas diferentes. Sistemas de Rastreamento de Candidatos (ATS) rejeitam automaticamente currículos que não contêm as palavras-chave exatas da descrição da vaga, muitas vezes antes de qualquer humano ler uma linha.

Adaptar o currículo manualmente para cada vaga consumia tempo demais. Então construí uma ferramenta para fazer isso por mim.

A Solução

O Polymorph é uma CLI que lê a descrição de uma vaga, analisa o currículo base em JSON e usa o Google Gemini 2.5 Flash para reordenar skills por relevância, reescrever o resumo profissional e adaptar as descrições de experiência e projetos — sem inventar informações, apenas reorganizando e enfatizando o que já existe. O resultado é um PDF profissional gerado em menos de 30 segundos via Playwright + Chromium headless.

O currículo que você está avaliando agora passou pelo Polymorph.

Pipeline de Execução

O processamento acontece em três estágios encadeados. Ao rodar python polymorph.py apply, o script captura o texto da vaga e envia um prompt estruturado para o Gemini Pro, que reordena skills e adapta o resumo profissional. O JSON retornado pela IA é injetado num template via Jinja2, mantendo separação total entre dados e design. Por fim, um navegador Chromium headless via Playwright renderiza o HTML e gera um PDF vetorial de alta fidelidade.

Engenharia de Borda

O caminho feliz é simples. O que diferencia o projeto são os casos que a maioria ignora:

  • Batch Mode: O comando batch processa uma pasta inteira com dezenas de descrições de vagas de uma só vez.
  • Smart Caching: O sistema armazena resultados localmente para evitar chamadas repetidas à API para a mesma vaga, economizando tokens e tempo.
  • Resiliência: Tratamento automático de RateLimitError da API do Google garante que um processamento em lote não falhe no meio sem aviso.

O que eu faria diferente

O modo batch atual é síncrono e bloqueante — processa vagas uma a uma, travando o terminal. Para dezenas de candidaturas simultâneas, adicionaria uma fila assíncrona (Celery + Redis) com feedback de progresso em tempo real. O maior risco de design atual é a dependência de um único provider de LLM: renomear gemini_client.py para llm_client.py e abstrair a interface tornaria a troca de provider (Gemini → Claude → GPT) cirúrgica, sem tocar na lógica de prompt ou na geração do PDF.
